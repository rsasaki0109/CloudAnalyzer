User guide

The web viewer opens and analyses point clouds in your browser. Files are read locally and never uploaded. Each section links to a demo that loads sample data and runs the analysis.

Opening data

  • Drop files anywhere on the page, or use Open…. Several files can be opened at once.
  • Point clouds: PLY, PCD, LAS/LAZ and XYZ-style text (.xyz .txt .csv .pts .asc). Meshes: OBJ, STL and PLY with faces.
  • RGB, intensity and classification are read when the file has them, and so are normals (nx ny nz) in PLY.
  • Open URL downloads a file from a web server. The server must allow cross-origin requests (CORS).
  • COPC files (.copc.laz) are not downloaded whole: the viewer reads every octree level that fits Max points per file with range requests, so large public datasets open in seconds. Try a 10.6M-point tile.
  • Georeferenced clouds (UTM, ECEF) keep full precision. A shared global shift, taken from the first file, is applied for display only and shown in the status bar.

Use Fit (F) and the Top, Front, Side and Iso views to reset the camera. Point size, EDL (depth shading) and Point budget (points drawn at once) are in the toolbar. On a phone, Panels opens the side panels as a sheet.

Next to the point size, Adaptive draws each point as wide as the local point spacing (in scene units), so surfaces close up when you come near; EDL is off in that mode. The colour swatch sets the background. Views remembers camera positions under a name, to come back to them; they are part of share links and sessions.

Coloring and classes

Each cloud in the list has a color mode: RGB, intensity, classification, solid color, distances, normals or hillshade. When a cloud has ASPRS classes, the Classes panel shows or hides each class in every cloud.

Distances (C2C, C2M)

In Distance, pick the compared cloud and the reference, then press Compute:

  • Against a cloud (C2C), each point gets the distance to its nearest reference point.
  • Against a mesh (C2M), each point gets the distance to the surface. With signed, points behind the surface are negative.

The result is shown with a color ramp, an adjustable range, a colorbar and summary statistics (mean, RMS, percentiles).

Try: two LiDAR scans

Change detection (M3C2)

Choose Method: M3C2 in the Distance panel. At each core point, a normal is fitted to the reference within the normal radius. Both clouds are then averaged in a cylinder of the projection radius along that normal, up to the max depth. The result is a new cloud with:

  • m3c2_distance, the change along the normal;
  • lod95, the 95 % level of detection;
  • significant, which is 1 where the change exceeds the level of detection.

Core points where either cylinder has too few points are grey.

Try: a landslide

Cut / fill volume

In Volume, pick a before and an after surface. Each can be a cloud, a mesh or a constant height. Both are rasterized on a grid of the chosen cell size, using the mean, lowest or highest point per cell. Fill empty cells interpolates holes.

The result gives the added (fill), removed (cut) and net volume and the areas, with the height difference of each cell shown as a cloud.

Try: a stockpile

Alignment (ICP)

In Registration (ICP), Align moves one cloud onto a reference, point-to-plane or point-to-point. It can pre-align the centroids and trim non-overlapping points. The panel shows the RMS before and after and the 4×4 transform, and Undo alignment reverts it.

Filters and ground extraction

Each filter creates a new cloud and keeps the original:

  • Voxel subsampling keeps one point per cube of the given edge.
  • Random subsampling keeps a given number of points.
  • Remove outliers (SOR) drops points whose mean distance to their k neighbours is more than ratio standard deviations above average.
  • Extract ground (CSF) drops a simulated cloth onto the upside-down cloud. Points close to the cloth are ground. Output is a copy classified ground / other, or only one of the two.
Try: ground extraction

Normals

Compute normals fits a plane to the k nearest neighbours of each point. The normals face up, or away from the cloud's centre. They are shown by the Normals color mode (direction as RGB) and the Hillshade mode (lit from the north-west). They are saved in PLY as nx ny nz.

Merge and split

  • Merge visible clouds builds one cloud. Colors and attributes are kept, clouds without RGB take their display color, and a source attribute records each point's cloud.
  • Split makes one cloud per classification code, or turns a merged cloud back into its files.

Clipping and cropping

Clipping box limits the view to a box set with per-axis sliders. The X, Y and Z buttons cut a thin section and look straight at it. Crop copies the points inside the box into new clouds.

Lasso segmentation and undo

Segment (S) draws a lasso: click around the points to cut out (Backspace removes the last vertex), then Keep inside (Enter), Remove inside (Delete) or Split into both parts. It cuts every visible cloud through the depth of the view, and skips points hidden by the clipping box or a hidden class.

↶ / ↷ (Ctrl+Z / Ctrl+Shift+Z) undo and redo segmentation, cropping, filters, ground extraction, merge, split, M3C2, volume and ICP. Removing a cloud with ✕ is not undone: it frees the memory right away.

Cross-section profiles

Press Draw line and click points on the view (a top view works best). Finish with a double-click or Enter. Every visible cloud's points within the band width are plotted as distance along the line against height, in the cloud's color.

Hover over the plot to read values. 1:1 uses the same scale on both axes, and Save CSV writes cloud, distance, x, y, z. Drawing a profile across two surveys compares them directly.

Picking and measuring

Click a point to see its exact coordinates, color and distance value. Measure (M) takes two clicks and shows their distance and ΔX / ΔY / ΔZ. Esc cancels.

Label (L) puts a text label on the point you click. It starts as the point's height, and you edit the text in the Labels panel. Labels are part of share links and sessions. Image saves the view as a PNG, with the labels, measurements, colorbar and profile plot drawn on it.

Saving results

The ⤓ button next to a cloud saves it as binary PLY, and the Distance panel also saves CSV. The file includes colors and all attributes: intensity, classification, normals, M3C2 fields and distances as scalar_C2C_distance. CloudCompare reads these as scalar fields.

Sharing and sessions

  • Share copies a link to the current view. It includes the camera, display settings, each cloud's visibility, color mode and ICP transform, recomputed distances, hidden classes, the clipping box and the profile line.
  • Clouds opened from a URL, and the demos, are downloaded again by whoever opens the link. Local files are not uploaded, so the link asks for them by name.
  • Save session writes the same state to a JSON file. Open it together with its files, or first.
  • A link like …/app/?url=https://example.com/scan.laz opens a remote file directly (the server must allow CORS). ?demo=volume starts a demo.

Large files

  • LAS and binary PLY/PCD are streamed in 16 MB slices. The progress bar shows how far a load is, and Cancel stops it.
  • Files above Max points per file (50M by default) keep every n-th point.
  • Only the octree nodes that matter on screen are drawn, up to the point budget.
  • Heavy steps run on a pool of workers: indexing, C2C/C2M, SOR and normals.
  • The status bar shows the viewer's WebAssembly memory. Reload the page to free it after closing big clouds.

Checked against CloudCompare

C2C, SOR and CSF give the same results as CloudCompare 2.13 on a public LiDAR tile. M3C2 agrees to a thousandth of a foot, and ICP, normals and volume are close. The validation report has the numbers and the differences in conventions.

Python

The same Rust core is available to Python as cloudanalyzer_core, multi-threaded. It covers reading, C2C/C2M, ICP, filters, CSF, volume, M3C2, profiles and normals. It is not on PyPI yet; build it from rust/crates/ca-py with maturin, as the README explains.

The demo clouds (stockpile, town, landslide) are synthetic and generated by web/scripts/make-samples.mjs. The two LiDAR scans derive from the public RELLIS-3D example (CC BY-NC-SA 3.0).
