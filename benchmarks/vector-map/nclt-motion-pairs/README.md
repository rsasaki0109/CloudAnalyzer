元の点群・車線・接続・監査・試行予算と、候補の軌跡評価は変更していません。

分母は元オドメトリの保持スキャン間XY経路長250.488575 / 252.724385 mです。
古い/新しい補正軌跡の距離を直接比較せず、同じ元スキャンID・時刻を介して
各HD区間を共通軸へ区分線形で対応付けました。各軌跡の生の分母・範囲も保存しています。
これは時間の対応であり、物理的な道路同一性や路面精度を証明する対応ではありません。

新しい提案を全てinspectし、固定幅(4月2.5 m / 6月2 m)を両端断面で満たす連続区間を
includeし、狭い区間をdeferしました。元と同じsource-spanの単一順方向・40 km/hの
**未検証の仮説**です。提案・断面・意思決定と全生成物を保存しています。
生成範囲が増えても要求する90%には未達です。

4監査は完了し構造・export errorはありません。低分位方式と層方式は異なる結果です。

IRとOSM再読込の結果はそれぞれ同じです。範囲・サンプル・車線自体が変わった集計で、
物理精度の改善を示す差ではありません。新しい車線は12 / 15本、接続は生成していません。
元地図の明示接続を引き継がず、経路と元の欠損を比較に残しています。
元地図4月は追加融合フレームを含み、候補は保持ノードのみを再融合しています。

比較ディレクトリの独立したselectionをbaseline → candidate → baselineへ切り替え、
最終revision 2で元の点群・HD地図の正確なartifact組へ戻しました。
元run・trial・完了した新runの全ファイルを前後で照合し、変更なしを確認しています。
`receipt.json`は件数と照合manifestのdigestを記録します。この保存済みreceiptは
ライブ確認の記録であり、原点群を含まない本packetだけで元ファイル全体を再検査する
ものではありません。地図品質や配備を認証する採用操作も実行していません。

`python benchmarks/vector-map/nclt-motion-pairs/verify.py` は標準ライブラリだけで、
全packetファイルのハッシュ、前の参照評価・motion trial packetとの対応、
共通距離/時刻/frame区間の再計算、獲得・喪失、4監査の全車線trace集計、
MCPで選んだ/復元した正確な組を確認します。元ログ・生スキャン・全点群・nativeは
含まず、ICP/路面監査の再実行、独立したHD精度、最適な位置合わせ、参照不確かさ、
未使用走行や別センサーへの一般化は検証できません。
